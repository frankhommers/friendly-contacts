# Sync all Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Sync all contacts" tab that scans every contact note, lists each one that differs with today's review next to it, and applies one contact or all that are ready.

**Architecture:** The per-contact round in `src/sync/syncFlow.ts` is split into `prepareRound` (choose book, prepare, build the review request) and `commit` (Apply), and `syncFlow` is rebuilt from them, so the single Sync and Sync all share one pipeline. A pure model `src/sync/syncAll.ts` scans with it, keeps per-contact choices, and on Apply always prepares again and applies only when the fresh review equals the one shown. A thin Obsidian `ItemView` renders the model with the reused `SyncReviewContent`.

**Tech Stack:** TypeScript, React 18 (`react-dom/client`), Obsidian API, vitest (+ jsdom for UI), esbuild; e2e against Radicale 3.8.3.

**Spec:** `docs/superpowers/specs/2026-10-23-sync-all-design.md`

## Global Constraints

- No second merge implementation: Sync all calls `prepareRound`/`commit` only; `prepareSync`, `applySync`, `reviewRows` are not copied or forked.
- Nothing is written before Apply, except the existing base write in `prepareSync` when both sides agree.
- Never apply choices to data other than what was shown: Apply re-prepares and compares (`sameReview`).
- The `running` lock in `src/sync/sync.ts` is held only while a note is scanned or applied.
- `sync: false` (boolean `false`, or the text `false` in any case, trimmed) in a note's frontmatter: never synced; not listed; "Sync this contact" refuses with the Notice `Not syncing <name>: sync: false is set in this note.`
- "Apply all that are ready" skips contacts with an open conflict and new cards (no card on the server yet); its count excludes them.
- Server-only cards are never listed.
- Pure modules (`src/sync/syncFlow.ts`, `src/sync/syncAll.ts`) import neither `obsidian` nor `src/context/` (checked by `tests/pureModules.spec.ts`).
- UI text is English, labels name the address book (`request.serverName`), never a fixed "Radicale" or "phone".
- Git: no Co-Authored-By lines, no mention of an LLM or agent in commits.
- Tests: `npx vitest run`, build: `npm run build`, e2e: `RADICALE_PYTHON=/tmp/radtest-t6/bin/python npm run test:e2e`. Write `\\;` in TS test sources with `String.raw` (the shell mangles it).

## Review Focus

1. A note edited, or synced on its own, between the scan and Apply: Apply must show the fresh review with the note "changed since the scan" and write nothing (Task 4 tests this for the note and for the card).
2. The scan's listing lookup must give the same answer as the per-UID search: a card whose UID the note spells `urn:uuid:X`, and a book whose listing cannot be read (must end as "could not search …", never as a new card) (Task 3).
3. A single Sync open in a modal while the scan reaches that note: the item is "cannot be synced" with a reason, and the lock is released after every scanned note, also when preparing throws (Task 3).
4. "Apply all that are ready" with a conflict left open, a new card, and a contact that changed meanwhile in one batch: only the ready one is written, the others stay listed (Task 4).
5. `sync:` values `false`, `"False"`, `" false "` turn Sync off; `true`, absent, `"no"` do not (Task 1).

**Interfaces:**
- Consumes: `prepareRound`, `PreparedRound`, `ReviewRequest`, `SyncFlowDeps` (Task 2).
- Produces:
  ```ts
  export interface SyncAllNote { path: string; name: string }
  export interface SyncAllDeps {
    /** Contact notes to scan, `sync: false` already left out. */
    notes(): SyncAllNote[];
    /** Flow deps for a note with these overrides, or why it cannot be synced (say: needs Convert). */
    flowDeps(path: string, over: { notify(message: string): void; adapterFor?: SyncFlowDeps['adapterFor'] }): Promise<SyncFlowDeps | { refused: string }>;
    /** The one-Sync-per-note lock: a release function, or undefined when a Sync of the note is running. */
    lock(path: string): (() => void) | undefined;
    /** Notes prepared at once; default 4. */
    concurrency?: number;
  }
  export type Badge = 'conflict' | 'server' | 'obsidian' | 'newCard';
  type Base = { path: string; name: string };
  export type SyncAllItem = Base & (
    | { kind: 'upToDate' }
    | { kind: 'review'; request: ReviewRequest; badges: Badge[]; choices: Map<string, Choice>; rename: boolean; messages: string[] }
    | { kind: 'done'; messages: string[] }
    | { kind: 'blocked'; reason: string });
  export interface SyncAllState { items: SyncAllItem[]; scanned: number; total: number; busy?: 'scan' | 'apply' }
  export function badgesOf(request: ReviewRequest): Badge[];
  export function listedAdapter(adapter: AdapterInterface): AdapterInterface;
  export class SyncAll {
    constructor(deps: SyncAllDeps);
    get state(): SyncAllState;            // a new object on every change (for useSyncExternalStore)
    subscribe(listener: () => void): () => void;
    scan(): Promise<void>;                 // no-op while busy
  }
  ```
- `items` is sorted by `name` (`localeCompare`), so it is stable while results arrive.

**Rules the tests pin:**
- `badgesOf`: no server card (`request.prepared.server === undefined`) → `['newCard']` only. Otherwise, in this order: `conflict` if a changed row has `preselect === undefined`; `server` if a changed row has preselect `'server'` or `prepared.damagedNotePhoto`; `obsidian` if a changed row has preselect `'local'`, or `rewriteRelations`, `rewriteLinks` or `request.moveLine`.
- `listedAdapter(a)`: `getMetaByUid(uid)` answers from one `a.getMetaList()` per wrapper (memoised promise): the meta whose `cleanUid(meta.uid ?? '')` equals `cleanUid(uid)`, else `undefined`; a listing error is returned as that error for every lookup. Every other method passes through. The scan builds one wrapper per source id for the whole scan.
- `scan()`: `busy: 'scan'`, `total` = number of notes, then per note (at most `concurrency` at once): `lock` (undefined → `blocked`, reason `A Sync of this contact is already open.`), `flowDeps` (refused → `blocked` with that reason), `prepareRound` with `adapterFor` = the listed wrappers and `notify` collecting messages, then `discard()` on a review. `end` upToDate → `upToDate`; refused/failed → `blocked` with the result's message; review → `review` with `badgesOf`, empty choices, `rename: true`, the collected messages. An exception → `blocked` with its message. The lock is released in `finally`. `scanned` counts up per note; the listener fires per result.

### Task 4: The Sync all model: choices and Apply

**Files:**
- Modify: `src/sync/syncAll.ts`
- Test: `tests/syncAll.spec.ts`

**Interfaces:**
- Produces (on `SyncAll`, plus one export):
  ```ts
  setChoices(path: string, choices: Map<string, Choice>): void;
  setRename(path: string, rename: boolean): void;
  /** Prepare again (after an Import in the review), replacing the item. */
  refresh(path: string): Promise<void>;
  apply(path: string): Promise<void>;
  /** Paths "Apply all that are ready" would apply now. */
  readyPaths(): string[];
  applyAllReady(): Promise<{ applied: number; changed: number; failed: number }>;
  export function sameReview(a: ReviewRequest, b: ReviewRequest): boolean;
  export const CHANGED_SINCE_SCAN = 'Changed since the scan; check it again.';
  ```
- `sameReview`: equal `title`, `moveLine`, `rewriteLine`, `linksLine`, `photoLine`, `serverName`; and on `prepared`: `noteSnapshot`, `server?.raw` and `server?.etag` (both absent counts as equal), `JSON.stringify(rows)`, `rewriteRelations`, `rewriteLinks`, `damagedNotePhoto`, `target.sourceId`, `move?.from.href`. (A new card's random UID is not in its rows, so two prepares of the same new note are equal.)
- `apply(path)` (only for a `review` item; `busy: 'apply'` while it runs): lock (busy → message `A Sync of this contact is already open.` added, item kept); `flowDeps` with the real adapters and a collecting `notify`; `prepareRound`:
  - `end` upToDate → `done`, messages `['Already in sync.']`; refused/failed → `blocked`.
  - review and `sameReview(shown, fresh)` → `commit({ kind: 'apply', choices: item.choices, rename: item.rename })`: `end` done → `done` with the collected messages; `end` failed → stays `review` with the fresh request and the messages; `stale` → `refresh` and add `CHANGED_SINCE_SCAN`.
  - review and not the same → `discard()`, the item becomes the fresh review (choices reset, `rename: true`) with `CHANGED_SINCE_SCAN` in its messages. Nothing is written.
  - Lock released in `finally`.
- `readyPaths()`: `review` items whose badges do not include `newCard` and `canApply(request.prepared.rows, choices)`.
- `applyAllReady()`: applies `readyPaths()` taken at the start, one after another; `applied` = became `done`, `changed` = got `CHANGED_SINCE_SCAN`, `failed` = everything else.
- `apply`, `applyAllReady`, `refresh` and `scan` are no-ops while `busy` is set.

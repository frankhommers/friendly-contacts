# Part 0: Dates Without a Year Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Year-less and partial dates read as one readable note form (`--03-15`) and are written back in the form the card used.

**Architecture:** One pure module `src/contacts/friendly/dates.ts` converts between a card's date line and the note
value. The translator (`translate.ts`), the patcher (`patch.ts`) and note coercion (`merge.ts`) call it for mapping rows
with `format: 'date'`. The legacy record parser and the sidebar birthday sort get the same understanding.

**Tech Stack:** TypeScript, vitest.

**Spec:** `docs/superpowers/specs/2026-10-18-sources-review-folders-design.md`, Part 0.

## Global Constraints

- Commits: never add `Co-Authored-By` or mention any LLM/agent.
- Core modules under `src/contacts/friendly/` import nothing from `obsidian` and nothing from `src/context/*`.
- Test: `npm run test:run`. Build: `npm run build`. Both pass at the end of every task.
- Unchanged vCard lines are written back exactly as parsed (the same `VCardLine` object).
- Applies to every mapping row with `format: 'date'` (by default `birthday` and `anniversary`), never to a property name.

## Review Focus

1. **A user types `--0315` by hand on an Apple card that holds `1604-03-15` + `X-APPLE-OMIT-YEAR=1604`.** Same date:
   the line must stay the identical object. Test: Task 1 `hand-typed basic form on an apple line is unchanged`.
2. **YAML turns an unquoted `1975-03-12` into a Date**: still `1975-03-12` (existing coercion), and `--03-15` stays a
   string. Test: Task 1 `coerces dates from the note`.
3. **`X-APPLE-OMIT-YEAR` whose year differs from the value's year** (`X-APPLE-OMIT-YEAR=1604:1980-03-15`): a real year;
   the note shows `1980-03-15`. Test: Task 1 `apple param with another year keeps the year`.
4. **Date-times and text values** (`19800315T120000Z`, `VALUE=text:circa 1950`) on read and when edited on a 4.0 card.
   Test: Task 1 `non-dates on 4.0 get VALUE=text`.
5. **Sidebar sort with mixed values** (full, `--03-15`, `1985`, text, empty): no crash, unparseable last.
   Test: Task 2 `sorts unparseable birthdays last`.

### Task 1: Date conversion in the friendly translator

**Files:**
- Create: `src/contacts/friendly/dates.ts`
- Modify: `src/contacts/friendly/translate.ts` (`formatDate` / `fieldValue`), `src/contacts/friendly/patch.ts`
  (`patchField`), `src/contacts/friendly/merge.ts` (`coerceNoteProps`)
- Test: `tests/friendly/dates.spec.ts` (new), `tests/friendly/toFriendly.spec.ts`, `tests/friendly/patch.spec.ts`,
  `tests/friendly/merge.spec.ts`

**Interfaces:**
- Produces (in `dates.ts`):
  - `readDate(line: VCardLine): string`: the note value for a date line (empty string for an empty value).
  - `normalizeNoteDate(value: string): string`: `--0315` -> `--03-15`; anything else trimmed and unchanged.
  - `writeDate(note: string, line: VCardLine | undefined, version: string): { value: string; params: [string, string][] }`:
    value and params for an edited line (`line` given: start from its params) or a new line (`line` undefined: params
    are only what the date form adds). `version` is the card's `VERSION` value.
- Consumes: `VCardLine`, `getParam`, `unescapeText`, `escapeText` from `lines.ts`; `cardVersion(s)` in `patch.ts`.

Rules (from the spec's Part 0 tables):

| `readDate` input | Output |
|---|---|
| `19800315`, `1980-03-15` | `1980-03-15` |
| `--0315`, `--03-15` | `--03-15` |
| `1604-03-15` + `X-APPLE-OMIT-YEAR=1604` | `--03-15` |
| `1980-03-15` + `X-APPLE-OMIT-YEAR=1604` | `1980-03-15` |
| `1985`, `1985-04`, `---15`, `19800315T120000Z`, `VALUE=text` values | `unescapeText(value)` verbatim |

| `writeDate` note value | Line | Result |
|---|---|---|
| `--03-15` or `--0315` | has `X-APPLE-OMIT-YEAR=Y`, or version `3.0` | `Y-03-15` (Y defaults to `1604`), params keep/add `X-APPLE-OMIT-YEAR=Y` |
| `--03-15` or `--0315` | version `4.0`, no Apple param | `--0315`, params unchanged |
| `1980-03-15` or `19800315` | had `X-APPLE-OMIT-YEAR` | that param removed; style as next rows |
| `1980-03-15` or `19800315` | existing line, old value basic (8 digits) | `19800315` |
| `1980-03-15` or `19800315` | existing line, old value extended; or new line on 3.0 | `1980-03-15` |
| `1980-03-15` or `19800315` | new line on 4.0 | `19800315` |
| anything else | version `4.0` | `escapeText(note)`, params plus `VALUE=text` (not duplicated) |
| anything else | version `3.0` | `escapeText(note)`, params unchanged |

A `VALUE=text` param on an existing line is removed when the new value is a date.
